# PORTCAST 대시보드

부산항의 기상·해양 데이터와 풀컨테이너선 운항 데이터를 결합해, 환경 조건에 따른 체류시간과 터미널별 운영 변화를 보여 주는 Streamlit 대시보드입니다. (현재: 초안)

- 분석 노트북: https://github.com/PORT-CAST/Port_Cast_Final
- 화면: 전체 요약 · KPI 1(기상조건별 체류시간 차이) · KPI 2(특보 노출 여부별 체류시간 차이) · 기상 상황 점검

## 실행 방법

```bash
git clone https://github.com/PORT-CAST/Dashboard.git
cd Dashboard

python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt

python -m streamlit run app.py
```

`pip`, `streamlit` 대신 `python -m pip`, `python -m streamlit`을 쓰면 가상환경과 다른 Python이 섞이지 않습니다.

## 분석 자료 넣기 (필수)

Streamlit Cloud 배포를 위해 `data/` 폴더의 CSV 2개를 저장소에 함께 올립니다. 다른 데이터로 바꿀 때에도 아래 파일 이름을 유지하세요.

| 파일 | 쓰는 화면 | 만드는 곳 (Port_Cast_Final) |
|---|---|---|
| `data/체류시간_찐최종.csv` | KPI 1, 회귀 보정 모형 | `2.Data_Integrated Preprocessing/Code/체류시간_최종.ipynb` 출력 (33,994행 × 21열) |
| `data/PORTCAST_선박_기상_특보노출시간_최종.csv` | 전체 요약, KPI 2의 단순 비교 | `터미널_특보` 노트북의 최종 출력 (33,819행) |

회귀 모델 두 개는 모두 첫 번째 CSV를 사용합니다. API 키가 없어도 분석·모형·조작판은 동작합니다.

### 계산 기준 (기초 EDA 노트북 후반 항만별 분석 기준)

- 원본: 2021~2024년 6개 터미널 접안 기록 33,994건. 화면의 기초 KPI는 총작업량 0인 175건을 제외한 33,819건을 사용합니다. 회귀 모형은 별도 결측 삭제 표본을 사용합니다.
- 체류시간 = 터미널 출항시각 − 접안시각 (시각 차이로 재계산)
- KPI 1 = 비교 기상구간 체류시간 중앙값 − 기준 구간 중앙값
  - 돌풍(최대순간풍속 최댓값) 5 미만 / 5~8 / 8 이상 m/s, 풍속 중앙값 2 미만 / 2~4 / 4 이상 m/s
  - 유의파고 최댓값 0.5 미만 / 0.5~1 / 1~2 / 2 이상 m
  - 시정 최솟값 5 미만 / 5~10 / 10~30 / 30 이상 km (원본 10m 단위 500·1,000·3,000)
- KPI 2 = 특보 노출 집단 중앙값 − 비노출 집단 중앙값. 발효·종료 구간과 체류 구간이 양의 시간만큼 겹치면 노출입니다. 원본 전체 4,787건 중 총작업량 양수인 4,763건이 화면 분석 대상입니다. 두 CSV의 분석 대상 행에서 노출 판정은 일치합니다.
- 조건 제한 표본 (항만별, 5,395건)
  - 북항(BPTC_G·BPT_S): 5,000 ≤ GT < 10,000, 400 ≤ 총작업량 ≤ 600 (4,899건)
  - 신항(BNCT·HPNT·PNC·PNIT): 100,000 ≤ GT < 150,000, 2,000 ≤ 총작업량 ≤ 2,500 (496건)
- 10건 미만 집단은 그래프에 빗금, 표에 "표본 적음"으로 표시
- 증가량은 관찰된 집단 간 중앙값 차이이며 기상으로 생긴 지연시간이 아닙니다.

### 회귀 보정값 (KPI 1·2 화면)

KPI 화면의 단순 중앙값 차이 옆에 회귀분석으로 다른 조건을 맞춘 **보정 증가량**을 함께 보여 줍니다.

KPI마다 최종 회귀 모형 **하나만** 씁니다. 두 모형 모두 대시보드가 실행될 때 같은 자료로 직접 적합합니다 (`models.py`, 처음 한 번만 몇 초 걸림).
공통 표본: `data/체류시간_찐최종.csv`에서 결측이 하나라도 있는 행 삭제 (32,014건).

| 화면 | 모형 (노트북) | 식 | 적합 자료 | 신뢰구간 |
|---|---|---|---|---|
| KPI 1 · 기상 상황 점검 | **M4_time** (KPI1_final_multiregression) | 체류시간 ~ 신항더미 × (총톤수 + 총작업량 + 특보유무 + 기상 6개) + 월 + 요일 + 연도추세, 연속형은 학습자료 기준 표준화 | 2021~2024 전체 재적합 32,014건, R² 0.735 | 선박 × 14일 블록 이중 군집 |
| KPI 2 | **모형 4 + 월·요일·연도추세** (KPI2_final_multiregression) | 체류시간 ~ 터미널 × (총톤수 + 총작업량 + 특보유무 + 기상 6개) + 월 + 요일 + 연도추세, 기상은 학습 평균 중심화 | 2021~2023 학습 23,557건, R² 0.750 | 날짜 기준 HAC 28일 |

- KPI 1 보정값 = 같은 터미널에서 해당 기상변수만 기준 구간 대표값 → 비교 구간 대표값으로 바뀔 때의 차이
  - 항만 상호작용 모형이라 같은 항만(북항: BPT_S·BPTC_G / 신항: 나머지)의 터미널은 기울기가 같음
  - 유의파고 최댓값은 모형에 없어 보정값이 없음, 풍속 중앙값은 다중공선성으로 부호가 반대로 나올 수 있음
- KPI 2 보정값 = 다른 변수가 같을 때 특보 노출 − 비노출 (터미널별, 95% 신뢰구간·p값). 노트북 값과 같음 (예: BPT_S +1.09h, 0.21~1.97)
- 두 노트북의 설계행렬·계수·공분산을 재현한 결과가 대시보드와 일치합니다.
- 시간 검증: 2021~2023 학습, 2024년 8,442건 검증. KPI 1의 학습 모형은 MAE 3.113h / RMSE 4.279h / R² 0.769, KPI 2는 MAE 3.017h / RMSE 4.192h / R² 0.778입니다. 위 표의 적합 R²와 구분하세요.
- 단순 차이는 집단 중앙값 차이이고 회귀 보정값은 조건부 평균 차이이므로, 동일 통계량의 보정 전후로 해석하지 않습니다.

### 기상 상황 점검 (조작판 + 회귀 모형)

왼쪽 조작판에서 **돌풍 최댓값 · 순간최대파고 최댓값 · 시정 최솟값** 3개를 조절하면, 나머지 기상값(풍속 중앙값 · 유의파고 중앙값 · 시정 중앙값)은
과거 기록으로 예측해 채우고, 오른쪽에 평온 대비 예상 체류시간 변화(95% 신뢰구간)·안정/주의/위험 단계·변수별 기여도·터미널 비교를 보여 줍니다.

- 보완값 = 각 주 변수(돌풍/최대파고/시정 최솟값)와 값의 절대거리가 가까운 최대 400건에서 짝 변수 중앙값을 계산합니다. 여섯 변수를 한꺼번에 예측하는 별도 모형은 아닙니다. 같은 거리이면 원래 행 순서를 유지합니다 (`models.조건예측`).
- 세부 조정은 그 기록들의 1~99% 범위와 물리 관계를 함께 만족하는 0.1 단위 범위에서만 가능합니다. 조절할 범위가 없으면 고정값으로 표시합니다.
- 시작점 버튼(평온·강풍·높은 파도·저시정·폭풍급): 그 터미널에서 조건에 맞는 기록의 변수별 중앙값으로 슬라이더를 맞춤. 하나의 실제 항차와 같은 기상 조합을 보장하지 않음
- 증가량 = KPI 1 모형(M4_time)의 기상 계수(+신항이면 신항더미×기상 계수) × (설정값 − 평온값), 특보 스위치를 켜면 같은 모형의 특보 계수(북항 +0.67h, 신항 +0.74h)를 더함
- 예상 체류시간 = 보통 선박(그 터미널 총톤수·총작업량 중앙값) + 월·요일·연도추세는 그 터미널 기록의 평균
- 단계 경계는 임시값(2시간·5시간) → `criteria.py`의 `증가량기준`, 시작점 조건 → `models.py`의 `시나리오정의`
- 조작판의 최근접 보완·평온 기준·중앙값 선박·2h/5h 분류는 대시보드에서 추가한 시나리오 기능입니다. 기초 EDA/회귀 노트북의 검증 성능이 이 기능 전체의 성능을 보증하지 않습니다.
- 체류기간 기상 대표값을 비교하므로 현재·예보 기상으로 운항 안전도를 판정하는 도구가 아닙니다. 안정/주의/위험은 체류시간 증가량의 임시 분류입니다.

## AI 요약 기능 (Gemini) — 각자 API 키 필요

AI 요약 버튼은 Google Gemini API를 사용합니다. **API 키는 저장소에 포함되어 있지 않으므로 각자 발급받아 넣어야 합니다.** 키가 없어도 대시보드는 실행되며, 요약 기능만 동작하지 않습니다.

1. https://aistudio.google.com/apikey 에서 Google 계정으로 로그인 → **Create API key** (무료, 카드 등록 없음)
2. 예시 파일을 복사해 `secrets.toml`을 만듭니다.
   ```bash
   cp .streamlit/secrets.toml.example .streamlit/secrets.toml
   ```
3. `.streamlit/secrets.toml`에 발급받은 키를 넣습니다. (`config.toml`이 아닙니다)
   ```toml
   GEMINI_API_KEY = "발급받은_키"
   ```
4. 대시보드를 다시 실행합니다.

### 주의

- **Streamlit Cloud 배포 앱**은 파일 대신 앱 설정 → Secrets 칸에 `GEMINI_API_KEY = "발급받은_키"`를 넣습니다.
- **`secrets.toml`은 절대 커밋하지 마세요.** `.gitignore`에 등록되어 있지만, 커밋 전 `git status`로 한 번 더 확인하세요.
- 키를 팀원끼리 공유하지 말고 각자 발급받아 사용하세요. 키 주인의 무료 사용 한도를 함께 쓰게 됩니다.
- 무료 등급은 분당·하루 요청 수 제한이 있습니다. 한도를 넘으면 잠시 뒤 다시 시도하세요.
- 무료 등급에 보낸 내용은 Google 서비스 개선에 사용될 수 있으므로 비공개 자료는 요약에 넣지 마세요.
- 키가 노출되었다면 AI Studio에서 해당 키를 삭제하고 새로 발급받으세요.
- 요약 버튼은 분석 자료(data 폴더)가 있을 때 활성화되며, 현재 화면의 집계표를 Gemini에 보냅니다.

## 폴더 구조

```
app.py                  화면 구성과 메뉴
kpi.py                  KPI 1·2 계산 (자료 읽기, 기간·터미널·표본 거르기, 중앙값 차이)
models.py               KPI별 최종 회귀 모형 (KPI1 M4_time, KPI2 모형 4 + 달력) 적합, 보정 효과·신뢰구간
charts.py               그래프 (plotly)
ui.py                   색상, 상단 배너, 지표칸, 패널, AI 요약칸
data/                   분석 CSV 2개 (Streamlit Cloud 배포용으로 저장소에 포함)
criteria.py             기상 상황 점검 단계 기준(증가량 주의·위험 경계)
terminal_map.py         터미널 위치 개념도
requirements.txt        필요한 패키지
.streamlit/config.toml  테마·글꼴 설정
.streamlit/secrets.toml.example  API 키 예시 (복사해서 secrets.toml로 사용)
assets/                 배너 이미지(containership.png) 등
static/                 Pretendard 글꼴
```

## 바꾸는 곳

- 배너 사진: `assets/containership.png` 교체
- 배너 높이: `ui.py`의 `.hero` 스타일 `height:280px`
- 판정 기준: `criteria.py`
- KPI 계산 기준(구간, 조건 제한 표본 범위, 표본 적음 기준): `kpi.py` 위쪽 설정
- 그래프 색·모양: `charts.py`
